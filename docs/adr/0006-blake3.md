# ADR 0006 — BLAKE3 for checksums

**Status:** Accepted — 2026-07

## Context

Every imported file is fingerprinted (integrity, duplicate detection, pipeline reproducibility — `pipeline.md` §5). Import targets several thousand photos per minute: hashing must not be the bottleneck.

## Decision

Every checksum uses BLAKE3, computed over the complete file and stored as a BLOB (32 bytes).

## Consequences

* Throughput of several GB/s (SIMD, parallelizable): hashing keeps up with the disk.
* Cryptographic soundness: collisions are a non-subject.
* The reference Rust implementation is maintained by the algorithm's own authors.

## Alternatives rejected

* **SHA-256**: 5 to 10× slower, with no benefit for this use.
* **xxHash / CRC**: fast but not cryptographic; acceptable for a cache, not for the durable identity of a file.
* **MD5**: broken, and there is no reason to introduce it in 2026.
