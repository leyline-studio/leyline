# ADR 0006 — BLAKE3 pour les checksums

**Statut :** Accepté — 2026-07

## Contexte

Chaque fichier importé est empreinté (intégrité, détection de doublons, reproductibilité des pipelines — `pipeline.md` §5). L'import vise plusieurs milliers de photos par minute : le hachage ne doit pas être le goulot.

## Décision

Tous les checksums utilisent BLAKE3, calculé sur le fichier complet, stocké en BLOB (32 octets).

## Conséquences

* Débit de plusieurs Go/s (SIMD, parallélisable) : le hachage suit la vitesse du disque.
* Fiabilité cryptographique : les collisions sont un non-sujet.
* Implémentation Rust de référence maintenue par les auteurs de l'algorithme.

## Alternatives écartées

* **SHA-256** : 5 à 10× plus lent, sans bénéfice pour cet usage.
* **xxHash / CRC** : rapides mais non cryptographiques ; acceptable pour du cache, pas pour l'identité pérenne d'un fichier.
* **MD5** : cassé, aucune raison de l'introduire en 2026.
